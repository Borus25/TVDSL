# Отчёт — HW1. Лексер Funny: regex → ДКА → минимизация

## 1. Список регулярных выражений (приоритет = порядковый номер)

При равной длине совпадения (maximal munch) побеждает токен с **меньшим**
номером — поэтому ключевые слова идут раньше общего правила `IDENT`, а
двухсимвольные операторы (`==`, `!=`, `<=`, `>=`) — раньше односимвольных
с тем же префиксом (хотя maximal munch и так выбрал бы более длинное
совпадение независимо от порядка).

## 2. Пайплайн построения

```
32 regex ──(парсер + Томпсон, по одному NFA-фрагменту на токен)──▶ union NFA
                                                                        │
                                                          subset construction
                                                                        ▼
                                                                  полный ДКА
                                                        (с явной ловушкой TRAP)
                                                                        │
                                                        Hopcroft minimize
                                                     (начальное разбиение —
                                                      по меткам токенов, а не
                                                      бинарно F/¬F)
                                                                        ▼
                                                            минимизированный ДКА
```

## 3. Размер автомата до/после минимизации

Фактические числа, полученные командой `python3 main.py build`:

| Этап | Кол-во состояний |
|------|------------------|
| Объединённый NFA (Thompson, все 32 токена + новый старт) | **180** |
| ДКА после subset construction (полный, с ловушкой) | **79** |
| Минимизированный ДКА (Hopcroft) | **76** |

Минимизация "склеивает" в первую очередь длинные хвосты ключевых слов
(например, суффиксы `nction`, `turns`, `hile`, ...), которые после того,
как префикс уже однозначно определяет, к какому ключевому слову или к
`IDENT` мы идём, ведут себя идентично с точки зрения дальнейших переходов
и принятия — но не сокращаются полностью, поскольку каждая позиция внутри
слова ещё должна "видеть" ровно нужный следующий символ (иначе слово
перестаёт быть допустимым префиксом этого ключевого слова и превращается
в `IDENT`). Основная масса состояний (>70%) приходится на распознавание
9 ключевых слов посимвольно и на 11 операторов/разделителей — это
неизбежно при чисто посимвольном ДКА без отдельной пост-обработки
"IDENT, затем таблица ключевых слов" (мы сознательно решили задачу через
чистый ДКА с приоритетами, как того требует задание).

## 4. Ловушка (TRAP)

- В `automata.subset_construction` ДКА строится как **полный (total)**
  автомат: для каждого состояния и каждого символа алфавита (128 символов
  ASCII) переход определён явно. Любой переход, не выведенный из
  NFA-фрагментов (символ не подходит ни одному токену в данном
  состоянии), направляется в отдельное состояние `TRAP`.
- `TRAP` — не принимающее состояние с петлёй по всем 128 символам
  (`δ(TRAP, c) = TRAP` для любого `c`), то есть "чёрная дыра": попав в
  неё, автомат никогда не примет строку.
- Символы **вне алфавита** (код > 127, т. е. не-ASCII, например кириллица
  или эмодзи) обрабатываются на уровне токенизатора: такой символ сразу
  считается лексической ошибкой (эквивалент немедленного попадания в
  ловушку), не выполняя ни одного шага по ДКА.
- После минимизации ловушка гарантированно остаётся отдельным классом
  эквивалентности (она не принимающая и не эквивалентна ни одному другому
  непринимающему состоянию, у которого есть выход в принимающее состояние
  по какому-то продолжению) — проверено тестами `unknown_symbol_at`,
  `unknown_symbol_dollar_and_backtick`, `non_ascii_hits_trap`,
  `non_ascii_emoji`.

## 5. Тесты

`tests/test_cases.json` — 29 сценариев, включая все обязательные из
задания:

- пустая строка, строки только из пробелов/табов/CRLF;
- `0` (валидный `INT`), `00`, `01` (каждая — **два** токена `INT`, а не
  один, т. к. `0|[1-9][0-9]*` не допускает ведущий ноль перед другими
  цифрами);
- идентификаторы с `_`, включая ведущее подчёркивание и цифры внутри;
- все 9 ключевых слов + проверка, что `functions`, `iffy`, `lengths`
  (ключевое слово как префикс) распознаются как `IDENT`, а не как
  ключевое слово + хвост;
- все разделители `()[]{},;` и все операторы
  `+ - * / == != <= >= < > =`, включая maximal-munch без пробелов
  (`===!=<=>=<>` → `== = != <= >= < >`);
- комментарии `//...` до конца строки, пустой комментарий, комментарий
  в конце файла без `\n`, разграничение `/` (SLASH) от `//` (COMMENT);
- выход за алфавит (non-ASCII: кириллица, эмодзи) — попадание в ловушку;
- прочие неизвестные символы (`@`, `$`, `` ` ``) — лексическая ошибка с
  указанием позиции, без остановки разбора всей строки;
- цельный пример функции на Funny (все категории токенов вместе).

Все 29/29 тестов проходят **и** на полном ДКА, **и** на минимизированном
ДКА (`python3 main.py test`) — это заодно служит регрессионной проверкой
того, что минимизация не изменила язык, распознаваемый автоматом.

## 6. Формат вывода / экспорт таблицы переходов

`python3 main.py export` кладёт в `out/`:

- `dfa_full.json` / `dfa_full.csv` — таблица переходов полного ДКА;
- `dfa_min.json` / `dfa_min.csv` — таблица переходов минимизированного ДКА.

JSON содержит `start`, `trap`, список `states`, словарь `accepts`
(состояние → имя токена) и `transitions` (состояние → {код символа →
следующее состояние}) — этого достаточно, чтобы воспроизвести лексер на
любом языке без повторного построения НКА/ДКА (используется в P02, T0).
