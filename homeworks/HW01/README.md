# HW1 — Лексер Funny: regex → НКА → ДКА → минимизация

Реализация на **Python 3** (стандартная библиотека, без внешних зависимостей).
Полностью воспроизводима из CLI.

## Состав проекта

```
funny_lexer/
├── main.py                       # CLI-точка входа
├── funny_lexer/
│   ├── regex_engine.py           # мини-парсер regex → AST, построение Томпсона (AST → NFA)
│   ├── automata.py               # union NFA, subset construction (NFA → ДКА), явная ловушка
│   ├── minimize.py               # минимизация Хопкрофта (с учётом меток токенов)
│   ├── token_specs.py            # спецификация токенов языка Funny (regex + приоритет)
│   ├── build.py                  # сборка всего пайплайна: regex → NFA → ДКА → min-ДКА
│   ├── tokenizer.py               # токенизатор (maximal munch) поверх готового ДКА
│   ├── export.py                 # экспорт таблицы переходов в JSON и CSV
│   └── tests_runner.py           # прогон тестов из tests/test_cases.json
├── tests/
│   └── test_cases.json           # входные строки + ожидаемые токены/ошибки
├── out/                          # (генерируется) экспортированные таблицы переходов
├── README.md
└── REPORT.md                     # отчёт: список regex, размеры ДКА до/после, ловушка
```

## Запуск

Требуется Python ≥ 3.7, без сторонних пакетов.

```bash
# всё сразу: построить автомат, экспортировать таблицы, прогнать тесты
python3 main.py all

# только построить и вывести статистику размеров (NFA / ДКА / min-ДКА)
python3 main.py build

# построить + экспортировать таблицы переходов в out/
python3 main.py export --out-dir out

# построить + прогнать тесты (на полном И на минимизированном ДКА)
python3 main.py test

# построить + токенизировать произвольный файл с исходным кодом Funny
python3 main.py tokenize path/to/file.fun
```

Код возврата `test`/`all` — `0`, если все тесты прошли, иначе `1`.

## Как это работает (коротко)

1. **`token_specs.py`** — список `(имя_токена, regex)` для всех токенов
   Funny (ключевые слова, IDENT, INT, разделители, операторы, WS, COMMENT).
   Алфавит — ASCII `0..127`.
2. **`regex_engine.py`** — маленький recursive-descent парсер regex
   (`|`, `*`, `+`, `?`, `()`, `[...]`/`[^...]`, экранирование `\`) строит
   AST, затем классическая **конструкция Томпсона** превращает AST в
   NFA-фрагмент (по одному фрагменту на regex-токен).
3. **`automata.py`**:
   - `union_nfas` — объединяет все фрагменты в один NFA через новый
     стартовый узел с ε-переходами (как в lex/flex): каждому
     accept-состоянию присваивается пара `(имя_токена, приоритет)`.
   - `subset_construction` — стандартный **subset construction**
     (NFA → ДКА), с ε-замыканиями. При конфликте (несколько NFA-токенов
     принимают одну и ту же позицию) состояние ДКА помечается токеном
     с наивысшим приоритетом (меньший индекс в `TOKEN_SPECS`, ключевые
     слова идут раньше `IDENT`). Строится **полный (total)** ДКА: любой
     неопределённый переход явно ведёт в состояние-**ловушку**.
4. **`minimize.py`** — **алгоритм Хопкрофта**, обобщённый на несколько
   классов принятия (начальное разбиение — не бинарное F/¬F, а по всем
   различным меткам токенов + отдельный класс для непринимающих
   состояний, включающий ловушку).
5. **`tokenizer.py`** — токенизация по принципу **maximal munch**:
   из текущей позиции проходим по ДКА как можно дальше, запоминая
   последнюю принимающую позицию; лексема — от начала до неё. Символы
   вне алфавита (code > 127) или без единого принимающего продолжения —
   лексическая ошибка на этой позиции (не блокирует разбор остатка строки).
   `WS`/`COMMENT` строятся и распознаются, но не попадают в выходной поток
   токенов (см. `SKIP_TOKENS`).
6. **`export.py`** — таблица переходов ДКА (полного и минимизированного)
   сохраняется в `out/*.json` и `out/*.csv` — формат пригоден для прямого
   подключения к лексеру проекта на T0 (state → {код_символа: next_state},
   плюс `start`, `trap`, `accepts`).

## Интеграция в проект (T0)

Файлы `out/dfa_min.json` (или `.csv`) содержат таблицу переходов
минимизированного ДКА, полностью описывающую лексер: достаточно
десериализовать `start`, `trap`, `transitions`, `accepts` и повторить
цикл maximal-munch из `tokenizer.py` на любом языке.
