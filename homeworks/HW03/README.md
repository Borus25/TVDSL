## Конструкции языка

```text
function add(a: int, b: int) returns r: int {
  r = a + b;
}

function example(a: array<int>, enabled: bool) returns r: int
  requires length(a) > 0
  ensures r >= 0
{
  var x: int = 1;
  var inferred = x + 2;
  var delayed;
  delayed = 3;
  if (enabled) { r = add(inferred, delayed); }
  else { r = a[0]; }
}
```

Как в вашем HW2, `returns r: int` объявляет **именованную переменную результата**. Оператора `return` нет. Присваивание неизвестному имени не является объявлением: нужен `var`. Точки с запятой разрешены, но необязательны — это сохранённое правило HW2.

Поддерживаются `int`, `bool`, `array<T>` (в том числе вложенные). Тип функции представлен как `func(T1, T2)->R`. Имена функций можно использовать в выражении; `var h = f; h(1)` типизируется как вызов локальной переменной функционального типа. Отдельного синтаксиса аннотации `func` нет.

`string`, перегрузки, неявные приведения, литералы массивов, `break`, оператор `return`, функции без результата и first-class lambda не реализованы. Выбрано допустимое заданием подмножество типов; синтаксис HW2 сохранён и расширен аннотациями/`var`.

## Правила типов

| Конструкция | Правило |
|---|---|
| `+ - * /`, унарный `-` | Только `int`, результат `int` |
| `not`, `and`, `or` | Только `bool`, результат `bool` |
| `< <= > >=` | Два `int`, результат `bool` |
| `== !=` | Структурно одинаковые типы, кроме функций; результат `bool` |
| `a[i]` | `a: array<T>`, `i: int`; результат `T` |
| `a[i] = value` | Значение типа `T`; проверяется также индекс |
| `length(a)` | `array<T> -> int` |
| `store(a, i, value)` | `array<T>, int, T -> array<T>` |
| Присваивание | Типы цели и значения совпадают |
| `if`, `while` | Условие `bool` |
| `assert`, `assume` | Выражение `bool` |
| `requires`, `ensures`, `invariant` | Выражение `bool` |
| Вызов | Проверяются существование, вызываемость, число и типы всех аргументов |

`int` и `bool` не смешиваются, несмотря на особенности встроенных типов Python. Унификация рекурсивно проверяет структуру массивов и функциональных типов. Неявных преобразований нет.

## Области видимости

Первый проход собирает сигнатуры всех функций; второй проверяет тела. Разрешены прямые, рекурсивные и взаимные вызовы независимо от порядка определения.

Параметры, результат и объявления верхнего блока тела находятся в одной области функции. Поэтому `var x` при уже существующем параметре `x` — повторное объявление. Вложенный `{ ... }` создаёт новую область и разрешает shadowing. Инициализатор вычисляется до добавления нового имени: `var x = x + 1` во вложенном блоке читает внешний `x`, если он есть.

`requires` и `ensures` видят параметры и имя результата, но не локальные переменные тела. В `requires` результат ещё не инициализирован; в `ensures` доступен как итоговое значение. Каждое тело проверяется отдельно — локальные имена между функциями не протекают.

Дополнительно есть консервативная проверка определённой инициализации. После `if` без `else` новое присваивание не считается гарантированным; с `else` нужны обе ветви. Цикл может выполниться ноль раз. Именованный результат должен быть присвоен на всех статически рассматриваемых путях. Значения условий не вычисляются: даже `if (true)` рассматривается как обычное ветвление.

## Бонус: вывод локальных типов

- `var x = 1;` выводит `int`.
- `var b = 1 < 2;` выводит `bool`.
- `var copy = a;` при массиве сохраняет структурный тип массива.
- `var x; x = 1;` выводит тип по первому корректному присваиванию.
- `var x = 1; x = true;` выдаёт `E_ASSIGN_TYPE`; уже выведенный тип не меняется.
- `var x;` без корректного присваивания в области — `E_CANNOT_INFER`.
- Нельзя читать ещё не инициализированную переменную.

Тип закрепляется в порядке статического обхода и должен быть согласован во всех ветвях. Это локальный вывод по первому корректному присваиванию, не полиморфный Hindley–Milner.

## Ошибки без каскадов

Диагностика содержит стабильный код, текст и позицию `line:col` (нумерация с 1). Семантические ошибки не прерывают проверку следующего узла. Специальный тип `<error>` распространяет уже обнаруженную ошибку, не притворяясь `int` или `bool`.

Для `tests/neg_multiple_errors.funny`:

```text
error: use of undeclared 'y' at 2:7 [E_UNDECLARED]
error: cannot assign int to bool at 3:17 [E_ASSIGN_TYPE]
error: cannot assign bool to int at 4:16 [E_ASSIGN_TYPE]
```

Для `r=y+1+z` получается ровно две ошибки неизвестных имён. При этом `r=y+true` сообщает и неизвестное `y`, и независимую ошибку `true` в арифметике.

При ошибочном присваивании объявленному имени оно считается синтаксически инициализированным для восстановления; это не превращает программу в корректную, но предотвращает дополнительные сообщения, вызванные уже известной ошибкой. При невозможности вывода сообщение относится к месту объявления.

## Аннотированный AST для HW4

Сохранён формат узлов HW2: `node`, поля узла и `pos` вида `"2:7"`. Каждое выражение получает `type`: `"int"`, `"bool"`, `"array<int>"`, `"func(int)->bool"` либо `"<error>"`. Неинициализированные чтения и неверные выражения также получают явный ошибочный тип. `VarDecl` получает окончательный выведенный/объявленный тип. `Function` сохраняет имена параметров из HW2 и дополнительно хранит `param_types`, `return_type`, позиции объявлений и полную сигнатуру `type`.

CLI с `--json` возвращает:

```json
{
  "format": "funny-typed-ast/1",
  "ok": true,
  "ast": {"node": "Program", "functions": []},
  "diagnostics": []
}
```

Это схема оболочки; реальный пример полной непустой программы — `generated/demo.typed.json`. Для загрузки дерева используйте `from_dict(payload["ast"])`. Проверен round-trip через настоящий JSON, включая позиции и типы.

API:

```python
from main import compile_source
from funny_ast import to_dict

program, diagnostics = compile_source(source_text)
if not diagnostics:
    typed_ast = to_dict(program)
```

`--desugar` выполняет преобразование **до** семантической проверки, поэтому новые узлы `store` тоже аннотируются. Если вы вручную применили `desugar()` после анализа, повторите анализ, чтобы новые узлы получили типы. Наличие аннотированного AST не означает реализацию исполнения, IR или кодогенерации; это формат для следующих этапов.

## Тесты

`tests/manifest.json` содержит входные файлы и вручную заданные ожидаемые коды ошибок в порядке позиций. `tests/expected/pos_*.json` — эталонные аннотированные деревья, `neg_*.err` — точные сообщения с позициями. Дополнительно 30 независимых unit-тестов проверяют типы, scope, точные позиции, отсутствие каскадов, типы всех выражений, JSON round-trip, CLI, десахаризацию вложенных массивов, LL(1) без конфликтов и совпадение табличного/рекурсивного парсеров. Полные результаты: `generated/test_results.json`.

Из корня архива:

```bash
python3 run_all_tests.py
```

Это также запускает неизменённый HW2: 36 snapshot-сценариев и 17 unit-тестов. Сводка — `generated/all_checks.json`, журналы — `generated/hw2_*.log`, `generated/hw3_*.log`.
