## Какие особенности AST сохранены

- JSON использует `node`, не придуманное новое поле kind.
- Function.params — список имён, типы лежат в param_types.
- Function.returns — именованная переменная результата, тип — return_type.
- Каждый Expr имеет строковый type.
- Block.stmts, Assign.target/value, If.then/else, While.body/invariant используются как в вашем funny_ast.py.
- `VarDecl` может не иметь initializer; итоговый тип берётся из type после HW3.
- Массивы обновляются функционально, как описано в desugar() вашего HW3.
- Оболочка main.py содержит format/ok/ast/diagnostics.

## Честная граница выполненной проверки

В этой среде не было локальной копии всех модулей HW3. Поэтому полный запуск настоящего фронтенда не отмечен как выполненный. Реально проверено чтение эталонного AST из вашего репозитория, обработка его генератором/VM, новый IR на специально построенных тестовых AST, CLI HW04 и протокол subprocess на явно тестовом frontend.

Команда, которая выполняет настоящий сквозной прогон в вашем репозитории:

```bash
cd homeworks/HW04
python3 run_tests.py --hw3-dir ../HW03
```

Она не меняет HW3, компилирует все 35 приложенных .funny через ваш frontend, сравнивает IR до/после на эталонных входах и проверяет отказ на ошибке типов. Без флага статус интеграции в отчёте — `not_run`.

Новые `examples/*.ast.json` специально построены тестовыми конструкторами; они не выдаются за независимо сгенерированные фронтендом результаты. `tests/hw3_pos_types_ok.json` переносит прочитанный эталон HW3, форматирован заново и не является заявленной побайтовой копией Git blob.

В примерах лекции встречаются `let` и ранний `return`, но ваш HW3 их не поддерживает. Вместо подмены языка здесь сохранены `var` и `returns r: T`, а явный return добавляется в IR в конце функции.
