# Практика 3. LL(1) и устранение неоднозначностей

> Занятие 4, неделя 4, после L04. Ветка LL; альтернатива — P04. Начало HW2.
> P-код — идентификатор материала, не номер недели. [Календарь](README.md).

## Цели

- Применить преобразования грамматик для получения LL(1).
- Построить таблицу предсказаний и отладить рекурсивный спуск.
- Встроить лексер из P02, использующий результаты HW1, в LL(1)-парсер.

## План занятия (90 минут = 2x45 + перерыв 5)

P03 и P04 — две ветки одного занятия. Каждый студент выполняет одну ветку для HW2.
Преподаватель предоставляет каркас парсера и небольшую грамматику выражений для каждой ветки.

- 0:00–0:15: общая демонстрация LL и LR на одной последовательности токенов.
- 0:15–0:45: работа в выбранной ветке: одно преобразование грамматики, FIRST/FOLLOW и ключевые клетки LL(1)-таблицы.
- 0:45–0:50: перерыв.
- 0:50–1:20: заполнение каркаса выбранного парсера, подключение лексера P02, запуск тестов.
- 1:20–1:35: сравнение подходов по раздатке преподавателя, разбор одной ошибки, план HW2.

Обязательный минимум: разбор одной подграмматики выражений, один положительный и один отрицательный тест.
Упражнения ниже — банк для выбранной ветки и самостоятельного доведения HW2, а не два полных практикума за занятие.
Реализация обеих веток не требуется. Полный AST завершается после L05/P05 к сдаче HW2 на неделе 5.

## Материалы/инструменты

- Грамматика Funny в текущей редакции (подмножество шага T0/T1).
- Скрипт/утилита для вычисления FIRST/FOLLOW (опционально) или ручные таблицы.
- Лексер из P02, использующий результаты HW1.
- Тестовые программы (валидные и с ошибками).

## Упражнения (аудитория)

- Преобразовать 2-3 проблемных правила: убрать левую рекурсию, факторизовать общие префиксы.
- Посчитать FIRST/FOLLOW, составить таблицу предсказаний; отметить конфликтные клетки.
- Реализовать (или сгенерировать) рекурсивный спуск для основной группы нетерминалов; подключить лексер.
- Добавить режим паники: при ошибке пропускать токены до ближайшего FOLLOW выбранного нетерминала.
- Прогнать 2-3 позитивных и 2-3 негативных примера, убедиться, что ошибки диагностируются без зацикливания.

## Дополнительные упражнения и примеры

- Устранение левой рекурсии: `E → E + T | T`, `T → T * F | F` → отфакторизовать и привести к LL(1).
- Факторизация: `S → if E then S else S | if E then S` → привести к LL(1) или выбрать подходящую стратегию.
- FIRST/FOLLOW для грамматики выражений Funny (с учётом обессахаривания `a[i]=v`): выявить, какие нетерминалы конфликтуют.
- Panic mode: подобрать набор «синхротокенов» (например, `;`, `}`, `EOF`) и убедиться, что ошибки не зацикливают парсер.
- Сравнить ручной LL-парсер и генератор (если используете ANTLR в LL-режиме): различия в диагностике.

## Примеры входа/выхода

- Валидный пример: `function f(x:int) returns r:int { r = x + 1; }` → дерево без конфликтов.
- Невалидный пример: `function f(x) returns r { if (x) r = 1 else r = 2 }` (пропущены точки с запятой) → режим паники
  должен восстановиться на `}`.
- Пример неоднозначности: `if (a) if (b) r=1; else r=2;` → показать, как LL-версия разрешает dangling else.
