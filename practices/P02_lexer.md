# Практика 2. Генерация лексеров (flex/lex)

> Занятие 3, неделя 3, после L03; предпосылка — P01. Лексер готовится к HW2.
> P-код — идентификатор материала, не номер недели. [Календарь](README.md).

## Цели

- Сгенерировать рабочий лексер из регулярных выражений.
- Добавить фильтры/предикаты для пробелов и комментариев.
- Согласовать формат токенов (вид, лексема, позиция) под проект/HW2.

## План занятия (90 минут = 2x45 + перерыв 5)

- Блок 1 (0:00–0:45): повтор регулярных выражений/ДКА из практики 1; longest match и порядок правил; обзор Lex/Flex (структура,
  секции, макросы, start conditions, приоритет/жадность).
- Перерыв (0:45–0:50).
- Блок 2 (0:50–1:35): демонстрация сборки лексера Funny (IDENT/INT/OP/KEYWORD), добавление WS и `//...` с позициями;
  обработка ошибок (ловушка, диагностика); небольшие положительные и отрицательные тесты; контрольный перечень готовности
  и подготовка лексера для будущего HW2.

## Материалы/инструменты

- Flex/Lex (или генератор для выбранного языка), компилятор/рантайм.
- Набор регулярных выражений из практики 1 (IDENT, INT, WS, COMMENT, OP/KEYWORD).
- Пример входа для тестов:

  `function f(x, y) returns r { r = x + y; // comment\n if (r > 0) { assert r == x + y; } }`

- Скрипт/утилита для сравнения полученных токенов с эталоном (список kind/lexeme/line/col).
- Алфавит: ASCII (как в спецификации Funny).

## Упражнения (аудитория)

- Реализовать лексер для IDENT/INT/OP/KEYWORD; настроить longest match (порядок правил + жадность, разбор IDENT vs KEYWORD).
- Добавить фильтры: пропуск WS; комментарии `//...` (start conditions), корректно обновлять счетчики строк/столбцов.
- Выводить токены в формате `{kind, lexeme, line, col}`; для ошибок печатать неизвестный символ и позицию, переходить в
  ловушку или пропускать по решению.
- Прогнать небольшой набор тестов (2-3 строки), сверить с эталоном.

## Дополнительные упражнения и примеры

- Longest match + порядок правил: `==` vs `=`, `else` vs `IDENT`, цепочки операторов `<= < >= >`.
- Краевые случаи: `0`, `00` (отрицательный пример), идентификаторы с `_`/цифрой в середине, пустые/пробельные строки, CRLF.
- Ошибки: non-ASCII символы → ловушка; незакрытый комментарий (если добавите `/*...*/` как опцию).
- Производительность: оценить количество состояний/правил в сгенерированном лексере на наборе тестов.

## Примеры входа/выхода

- Ввод: `function add(x,y) returns r { r = x + y; // sum\n}`  
  Выход (пример): `FUNCTION("function",1,1) IDENT("add",1,10) LPAREN(1,13) IDENT("x",1,14) COMMA ...`
- Ввод (ошибка): `foo @ 42` → токены до `@`, затем ошибка с позицией (строка/столбец), переход в ловушку.
